## 问题与排查范围

用户反馈：浙工大后台账号创建比赛提示“内容安全校验失败，请稍后重试”，管理员账号可以创建；同一时间段两个校区无法同时签到，需确认是否按学校划分。

本轮检查源码、近期提交、仓库 backend/.env 配置的数据库（仅 SELECT）和小程序配置的公开只读签到点接口。未创建真实赛事或签到、未修改数据库或业务代码、未提交或部署。数据库结果和公开接口签到点的 ID、名称、时间、学校归属一致；这不证明线上后端/小程序已部署当前 Git HEAD。

## 阶段结论：比赛创建

### 已证实

1. 浙工大初始化学校账号为 `zjgydx`。`backend/scripts/seed-school-admins.js:168-170` 写入 `admin_${username}` 作为 openid。2026-10-25 下午（北京时间）数据库只读核查确认：该账号 id=10，school_id=3，具有有效 school_admin 角色，openid 属于 `admin_` 占位值。查询仅输出 openid 类型，不输出真实用户 openid 或密码。
2. `backend/routes/admin.js:636-661` 中，不同后台角色创建赛事都调用同一 `assertSafeSubmission`，且先校验、后 INSERT；没有超级管理员免审分支。
3. `backend/utils/contentSecurity.js:331-359,479-494` 从该后台用户查询 openid，**只判断是否非空**。`admin_zjgydx` 非空，因此被写入 version=2 的微信请求。
4. 提交 `53ea5f7`（2026-04-01）的无 openid 回退只处理 null/空值，覆盖不到 `admin_` 占位值。
5. `backend/utils/contentSecurity.js:459-476,572-583` 将非内容拒绝类的接口错误转换为统一 503 提示“内容安全校验失败，请稍后重试”。处理后不输出 error.details；因此不能只从页面提示判断真实微信 errcode。违规内容的提示是“发布内容未通过审核，请修改后再试”，属于不同分支。
6. 本次查到的两个超级管理员账号的 openid 均为非占位值；未请求微信验证其有效性或近期访问状态。

### 判断与待验证

学校后台占位身份进入微信审核，是与“学校账号失败、管理员账号成功”高度吻合的确定代码缺陷。实际失败请求是否返回 invalid openid，以及是否还包含图片校验/凭证等其他失败，需要原始微信返回闭环，不能编造具体错误码或声称线上修复成功。

修复方向：将后台登录身份与真实微信审核身份区分，识别项目自己生成的占位 openid，明确无真实微信身份时采用的有效审核方案。保留内容审核；不要通过提升学校账号权限或跳过审核解决。既有 version=1 回退的线上可用性本轮未向微信验证，不据此承诺直接回退即可恢复。

## 阶段结论：签到范围与同时使用

### 学校归属、时间与位置

- `backend/routes/checkin.js:43-64`：传 school_id 时返回“本校 + school_id IS NULL 通用”全部 active 点，按距离排序；未传时不做学校过滤。学校归属用于点列表筛选。
- `backend/routes/admin.js:1388-1435`：学校管理员按 managedSchoolIds 看点，新建点强制使用 managedSchoolIds[0]，直接 INSERT，无同校同时段互斥校验；更新按点 id，仅修改该行。
- `backend/migrations/006_checkin.sql` 及 024/026/031：签到点有 school_id、坐标、半径、每点开始/结束时间，无 campus_id，也无“同学校仅能存在一个签到点/时间窗”的唯一约束。
- `pages/check-in/check-in.js:79-142,272-307`：有未签退记录时优先原点；否则先选时间有效点，再比较距离，页面只显示一个目标点，无手动选校区入口。同样有效的两个点会随各自用户位置选择最近的点。
- `backend/routes/checkin.js:72-110`：实际签到按提交 point_id 查该点的时间窗和定位半径，不设学校占用锁。

### 每人每天限制

`backend/routes/checkin.js:19-40,112-130`：

1. 同一用户今天任何点有未签退记录，提示先回原点签退。
2. 即使已签退，只要当天存在任意签到记录，就提示“今日已完成签到，请明天再来”。查询按 user_id+日期，**不按 point_id 或校区区分**。
3. `pages/check-in/check-in.js:155-188` 的页面状态也执行“当天已签退即完成”的限制。

因此应区分：不同学生在两个有效点同时签到，源码支持；同一个学生当天跨点再次签到，当前明确禁止。后者若要调整需先确认业务规则，不应直接把去重改成每点每日一次。
