# 审核身份修复、赛前取消领队和校区签到：设计与实施计划

> 执行方式：当前会话逐项实施并检查，不提交或部署。使用 writing-plans 的计划审查流程，设计选择遵循用户当前授权。

**目标**：修复学校后台创建赛事失败；允许学校管理员赛前取消已申请的领队资格；在小程序与后台完整支持校区筛选。

**技术栈**：Express/MySQL、Vue 3/Element Plus、微信小程序、Node assert/VM 隔离测试。

## 已确认需求与设计

- 用户明确授权三项实施；校区范围通过异步答复确认：小程序选择、后台签到点/记录/导出均支持，并在点中设置校区。
- 用户补充：领队申请只有比赛前可撤销，比赛已经进行或结束不能撤销。状态 pending、approved、rejected 均可在赛前取消；不存在申请则拒绝。
- 撤销仅影响申请及管理授权，保留球队关联、报名和成绩。报名中的 is_team_leader 作为既有球队结构标记保留，所有管理动作必须以申请 approved 为准；补齐旧接口遗漏的检查。取消后可重新申请，经审核恢复管理权限。
- 签到仍保持原“每用户每日一次”和原点签退规则。校区选择不能绕过未签退记录，也不能改写历史签到点关联。
- 通用签到点仍对所有学校可见；选择具体校区后仅保留 campus 相同的点，未设置字段的点单独归入“未设置校区”，不混入任意校区。校区选项始终从未按校区过滤的完整同校/通用点集合生成。
- 重新申请进入 pending 时清空 cancelled_by/cancelled_at；这些字段记录当前一次取消状态，不声明完整历史审计。取消事务同时锁申请、赛事和该赛事全部 matches 范围，阻止赛事/对局状态修改穿过校验；最后 UPDATE 再以数据库 NOW() 校验开始/结束边界并检查 affectedRows。

## 方案与取舍

1. 审核：识别项目已生成的 admin_/dev_/mock_ 占位身份，按已有无 openid 路径提交审核；真实 openid 保持 v2；服务失败与违规内容仍拦截。与更换审核供应商相比改动小，但既有 v1 服务线上可用性需部署后确认，不宣称已线上恢复。
2. 校区采用签到点 campus 名称字段，后台可输入或复用同学校区。相比建立独立校区管理系统，实现直接、无需改用户注册；相比从点名临时猜测筛选，字段明确、查询可索引。保留未设置校区选项，迁移只从浙工大点名中无歧义的朝晖/屏峰/莫干山词补齐元数据，不按坐标猜测、不删除点或记录。
3. 领队采用 cancelled 状态及 cancelled_by/cancelled_at，保留记录以区分拒绝和取消。取消需学校管理员管理赛事所属学校，或超级管理员；赛事管理员不能取消。赛前条件校验包含显式 ongoing/finished/cancelled 状态、开始/结束时间和实际已进行的对局。取消在事务和行锁内处理；审批仅接受 pending，避免旧界面把已取消状态重新批准。

## 实施审查中的补充发现

- 独立只读审查确认 `pages/invitations/invitations.js` 实际调用的 `backend/routes/user.js` 旧邀请响应入口，不受 events token 入口新增检查保护。已为旧入口补充事务内领队申请 `FOR UPDATE` 校验，取消后不能接受遗留邀请；离线测试先观测 200（错误），修复后为 403 且无写入。
- 单纯在队伍操作入口 SELECT approved 不足以撤权：在途请求可在取消提交后继续取消整队。已在草稿、邀请、正式提交、整队报名/加入/取消、队员移除、单打与项目分配的写事务中重新锁定申请并复核 approved，持锁到写入结束；补充“预检 approved、落库前 cancelled”的回归用例，确认无写入并回滚释放。
- 用户“领队申请是在比赛前”的边界也适用于重新申请。初审曾用 finished 赛事复现 cancelled 被改回 pending。现申请接口锁定赛事和对局，检查状态/东八区开始结束时间/已进行对局；实际 INSERT/UPDATE 再检查数据库 NOW()，重新申请同时清空当前取消字段。
- 后端 Docker 镜像仅包含 backend，根目录小程序 utils 不随镜像发布。签到与新领队工具使用 backend/utils/china-time.js 本地副本，回归比较双方时间解析行为；校区过滤的保留标识独立定义并与小程序契约用例对齐，避免上线 MODULE_NOT_FOUND。
- 旧客户端编辑签到点不带 campus 时必须保留原值；只有明确传空值才清空。已补充测试并修复。
- 后台构建使用程序化 Vite `build({build:{emptyOutDir:false}})`，在实际 backend/public/admin 中更新入口和新哈希资源，保留既有资源，不执行默认清理。构建成功；包体 >500kB 提示属于现有资源体积提示。
